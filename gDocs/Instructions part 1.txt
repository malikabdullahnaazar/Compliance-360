Standards engine design (CMS + CHAP + HHSC overlay)
“One requirement, many mappings”
Create a Common Requirement Library (CRL): each requirement has:
•	ID, title, description
•	Trigger (admission / recert / every IDG / discharge)
•	Evidence needed (doc types + fields)
•	Pass/fail logic + timing rules
•	Severity
•	Mapping table: CMS / CHAP / HHSC references + interpretation notes
This prevents “rewriting the same rule” three times.
Versioning (required)
Store:
•	Framework name + version + effective date
•	Interpretation set version (your internal “rule pack”)
•	Audit run includes these versions so results are reproducible later.

Starter requirement set (high-impact “Texas-ready” checks)
Below is a practical v1 CRL list (not exhaustive). Each becomes a rule with evidence links.
A) Eligibility & Election
1.	Election statement present and complete
o	Required elements present; patient/representative signature and date; attending physician info; effective date.
2.	Patient rights acknowledgment present
3.	Initial certification of terminal illness (CTI) present
o	Signed/dated by physician as required; within required timeframe.
4.	Terminal prognosis rationale supported in record
o	Clinical indicators consistent with diagnosis and narrative; avoid contradictions.
B) Recertification / F2F
5.	Recertification CTI present for each period
6.	Face-to-Face encounter completed when required
o	Timing + required elements + appropriate practitioner + attestation/signature rules.
7.	Narrative supports ongoing eligibility
o	Decline indicators across nursing notes vs recert narrative align (flag inconsistencies).
C) Plan of Care & IDG
8.	Comprehensive assessment timely and complete
9.	Plan of Care initiated and updated on required cadence
10.	IDG review documented with required cadence
11.	IDG includes required disciplines / input
12.	Goals/interventions tied to assessed problems
•	No “orphan interventions” without assessment basis.
D) Orders / Medication
13.	All orders present, dated, signed
14.	Verbal/telephone order documentation meets requirements
15.	Medication profile present and reconciled
16.	Hospice-related vs unrelated meds documented (if required by your policy/standard mapping)
17.	Allergy documentation present
18.	High-risk med monitoring prompts triggered (optional v1, strong v2)
E) Visit documentation
19.	RN visit documentation includes required elements
20.	SW documentation includes psychosocial assessment / interventions
21.	Chaplain/spiritual care documentation present when on POC
22.	HHA care consistent with aide plan
23.	Missed visits documented with follow-up
24.	Visit frequencies align to POC (variance documented)
F) Discharge / Death / Bereavement (v1-lite)
25.	Discharge reason documented (live discharge or transfer)
26.	Death documentation elements present
27.	Bereavement risk assessment and plan present
In v1, focus scoring + deficiencies on the “survey-cite magnets”: election/CTI/recert/F2F/POC/IDG/orders/signatures/timeliness.

Correction guidance (safe, non-fabricating)
Every deficiency produces a “Correction Card” with:
•	What is missing (specific fields)
•	Where it should live (note/form type)
•	Who should complete it (role)
•	What is allowed (addendum vs late entry vs new note)
•	Required attestations
•	A prompt checklist clinicians must answer (to ensure truthfulness)
•	Optional template wording with placeholders (no invented clinical facts)
Example (pattern):
•	Deficiency: Missing F2F attestation element
•	Correction: “Add F2F addendum including: date/time of encounter, practitioner role, summary of clinical findings supporting continued eligibility, practitioner signature/date.”
